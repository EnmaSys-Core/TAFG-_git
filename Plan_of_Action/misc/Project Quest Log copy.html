TAFG v2: Raw Blueprint

Mission & Philosophy

  • A Tool, not a Guidebook: The UI *is* the 3-step process.
  • ADHD-Friendly: Enforce focus ("One Brick") but provide an outlet ("Brain Dump").
  • Motivation via Proof: Build motivation by tracking tangible, "graspable" progress.
  • Safe to Fail: "Undo" and "Soft Delete" remove the anxiety of making a mistake.

Phase 1: Setup (The Critical Path)

Firebase Security Rules

These rules ensure users can ONLY read/write their OWN data. This is critical for privacy.

// (From Blueprint Sec 3)
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Users can only access documents in their own 'users/{userId}' path
    match /users/{userId}/{documents=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}

Phase 2: Global UI/UX (Robustness)

Build "Empty States"

Why: A new user opening the app to a blank white screen is demotivating and confusing. We must design a welcoming "Empty State" that actively guides them (e.g., "Welcome! Create your first Goal to get started.")

Implement CRUD Operations

Why: The app is useless if a user can't fix a typo or remove a bad idea. This is a non-negotiable requirement for a real tool. We need "Edit" and "Delete" buttons on all user-created content.

Implement "Soft Delete" & "Undo"

Why: To remove the anxiety of accidentally deleting something. We will use "Soft Deletes" (setting `isDeleted: true` instead of truly deleting). This provides a 5-10 second "Undo" window and makes a "Trash Can" feature possible in the future.

Implement User Feedback

Why: The app must communicate with the user. If they click "Save" and the internet is down, it can't just fail silently. We need to show "Loading..." (on save), "Saved!" (on success), and "Error: Check connection" (on failure).

Phase 3: Core Modules (The "What")

Module 1: Authentication

What: Handles Google Sign-in. This is the "key" to the app. It will manage the user's `userId`, which is required to fetch all their private data.

Module 2: "Comprehend" (Goals)

What: This is the user's "Goal Dashboard." It's a full CRUD module where a user can add a new "One True Thing" (a Goal), see their list of active Goals, select one to work on, edit its title, and delete it.

Module 3: "Deconstruct" (Workbench)

What: The core of the app. This tab is split in two:

  • "One Brick" List: A to-do list that *only* shows tasks for the *active* Goal. Enforces focus.
  • "Brain Dump" Notepad: A simple, auto-saving text area for all the other ideas, preventing the user from derailing their focus by adding them to the "One Brick" list.

Module 4: "Reconstruct" (Log)

What: A simple, motivating "Done" list. When a "Brick" is checked off in the Deconstruct tab, it moves here. This provides the "graspable proof" of progress, which is a key motivator.

Module 5: "Energy" (Log)

What: The "Two-Front War" log. A slider lets the user log their daily energy split ("Healing" vs. "Building"). A Chart.js line graph then plots this data over time, helping the user "Comprehend" their own patterns.
